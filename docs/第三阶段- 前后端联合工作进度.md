# 第三阶段 - 前后端联合工作进度

## 1. 文档职责

本文档是 Agent Phase 3 的唯一执行进度记录，汇总前端、后端实现、联调、测试和人工验收证据。它与 [第三阶段工作计划.md](第三阶段工作计划.md) 配套使用：

- `第三阶段工作计划.md` 是联合蓝本，定义范围、阶段目标、架构边界和最终验收标准。
- 本文档记录实现顺序、当前状态、验证证据和遗留事项；每个工作项都以一个前后端垂直切片描述。

Phase 3 完成、阶段结论和必要证据已提炼后，本文档与联合蓝本一并删除。下一阶段不再采用阶段计划/进度文档，而从 OpenSpec Explore/Change 开始管理详细工作。

## 2. 当前目标

完成首个真实、同步的 Tender Agent 业务调用：

```text
TenderPage：招标文件 + 用户关注点
  -> Tender HTTP 接口（multipart）
  -> 请求级临时解析
  -> 已发布知识库 RAG 检索
  -> Tender Application 调用 Structured LLM
  -> 结构化结论 + 真实来源引用
  -> 同一页面展示结果、资料不足或错误
```

该链路验证一个业务 Agent 对文件解析、RAG 和 LLM 的复用能力；它不实现任务运行时、会话上下文或多 Agent 编排。

## 4. 联合工作项

### P3-01：同步契约与模块边界

| 后端 | 前端 | 联合验收 |
| --- | --- | --- |
| 定义 multipart Request、Application Command/Result、引用 Result、错误语义、依赖 Port 和 Composition Root 装配。Route 只做协议适配。 | 在 `features/agent/tender/` 定义 API、types、Hook 和页面边界；API 层负责 `FormData` 与错误转换，页面不直接调用 Axios。 | 空文件、空关注点、格式/大小超限不会进入解析或模型调用；前后端只使用同一份字段和错误契约。 |

| 后端 | 前端 | 联合验收 |

| 后端 | 前端 | 联合验收 |

## 5. 明确不做

- `task_id`、任务状态、轮询、重试、取消、下载、持久化或恢复。
- 会话历史、上下文记忆、Conversation 模块。
- LangGraph、Function Calling、MCP、SubAgent、Agent Runtime 或多 Agent 编排。
- 招标文件入库、投标书骨架/正文生成、文件导出或人工确认工作流。
- 将 `/agents/tender/tasks/*`、骨架预览、工作流等 Mock 页面接入真实接口。

## 6. 架构检查点

```text
TenderPage
  -> HTTP Route / Schema / Assembler
  -> Tender Application
       -> 文件解析 Port / 已发布知识库检索 / Structured LLM Port
  <- Infrastructure 解析实现 / 检索实现 / LangChain Adapter
```

- HTTP 不直接调用 LangChain、Repository、文件解析器或模型 SDK。
- Application 不创建具体客户端、不读取环境变量；Domain/Ports 不依赖 FastAPI、LangChain 或前端类型。
- 前端只经 HTTP 使用后端能力，不接触数据库、Repository、模型或领域对象。
- 外部模型和检索在自动化测试中使用可控替身；真实调用只用于人工联调。
