## 2. 当前目标

完成首个真实、同步的 Tender Agent 业务调用：

```text
TenderPage：招标文件 + 用户关注点
  -> Tender HTTP 接口（multipart）
  -> 请求级临时解析
  -> Tender Application 调用 Structured LLM
  -> 结构化招标要求、风险点和投标书骨架
  -> 生成骨架文件并在同一页面展示
```

该链路验证一个业务 Agent 对文件解析、Structured LLM 和文件产出的复用能力，为后续 SubAgent 编排准备稳定的业务能力；它不实现公司资料库填充、任务运行时或会话上下文。

## 5. 明确不做

- `task_id`、任务状态、轮询、重试、持久化或恢复。
- 会话历史、上下文记忆、Conversation 模块。
- LangGraph、Function Calling、SubAgent、Agent Runtime 或多 Agent 编排；本阶段包含 MCP 能力适配，但不包含 MCP 编排。
- 招标文件入库、完整投标正文、人工确认和编辑工作流。
- 公司资料库检索、资料不足判断、建议生成、公司能力匹配和骨架内容填充；这些属于后续 V2。
- 将 `/agents/tender/tasks/*`、任务工作流等 Mock 页面接入真实接口；V1 的骨架预览/下载由新的同步页面负责。

## 6. 架构检查点

```text
TenderPage
  -> HTTP Route / Schema / Assembler
  -> Tender Application
       -> 文件解析 Port / Structured LLM Port / Skeleton Renderer Port
  <- Infrastructure 解析实现 / 文件渲染实现 / LangChain Adapter
```

- HTTP 不直接调用 LangChain、Repository、文件解析器或模型 SDK。
- Application 不创建具体客户端、不读取环境变量；Domain/Ports 不依赖 FastAPI、LangChain 或前端类型。
- 前端只经 HTTP 使用后端能力，不接触数据库、Repository、模型或领域对象。
- 外部模型和检索在自动化测试中使用可控替身；真实调用只用于人工联调。
