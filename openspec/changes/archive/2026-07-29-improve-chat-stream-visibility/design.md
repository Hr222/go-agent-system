## Context

现有前端使用 `fetch` 读取 `POST /api/v1/llm/chat/stream` 的 SSE 响应，并在每个 `delta` 回调中直接更新 Chat 消息。一次 `ReadableStream.read()` 可包含多个完整 SSE 帧，连续状态更新又会被 React 批处理，导致已接收的内容只在最终状态显示。

后端已经提供正确的 SSE 响应头、事件顺序与取消传播。本次只调整 React 前端，保持 HTTP 路径、请求体、事件名称和字段不变。

## Goals / Non-Goals

**Goals:**

- 让每个已接收的 `delta` 都进入可观察的页面渲染节奏，并保持服务端顺序。
- 在连接中、输出中、完成、取消和失败时展示准确且可持续辨识的状态。
- 将 `fetch`、`ReadableStream` 与 SSE 帧解析收敛到 `services/http`，让业务 API 不直接承担底层传输职责。
- 保持已显示和已接收的部分回答，不因完成、取消或失败而丢失。

**Non-Goals:**

- 不改变 FastAPI 路由、SSE 契约、超时配置、Provider、Prompt 或模型分块策略。
- 不模拟模型逐字生成，不人为拆分 Provider 返回的 `delta`，也不改变模型计费或总耗时。
- 不引入会话历史、持久化、Agent 编排、React Query 流缓存或新的第三方依赖。

## Decisions

### 1. 使用通用流式 HTTP 客户端承载 POST SSE

在 `services/http` 中放置专用流式客户端，负责 `fetch`、响应状态映射、`ReadableStream` 读取、跨分块 SSE 帧拼接、JSON 解码和 `AbortSignal`。Chat 业务 API 只声明流式 Chat 的请求与事件映射，页面仍经由 Hook 调用业务 API。

这是对“所有普通请求使用 Axios”的受控例外：浏览器 Axios 不提供所需的标准异步响应流迭代接口，而 `EventSource` 不能发送当前契约要求的 POST JSON Body。相比把底层读取继续留在 `features/chat/api`，该方式更符合 HTTP 基础设施与业务模块的分层。

### 2. 以 `delta` 队列和动画帧提交页面文本

Chat 页面或其专用展示 Hook 为当前助手消息维护先进先出的 `delta` 队列。网络回调只入队；渲染调度器每次动画帧按顺序取出一个或一批受限片段，使用函数式状态更新追加到该助手消息。输出中状态显示活动光标或等价指示，直到队列排空且终止事件已收到。

选择动画帧而不是在网络回调内直接更新，是为了给浏览器提交绘制的机会，并避免同一读取批次内的 React 自动批处理抹去中间状态。选择保留 Provider 的片段边界而不是逐字动画，避免伪造响应速度和对长回答造成无界滞后。

### 3. 终止事件延后到队列排空后提交

`complete`、取消或错误到达时先记录终止结果；若仍有待渲染的已接收片段，继续排空队列，再更新助手消息的 `completed`、`cancelled` 或 `failed` 状态。`complete` 的模型与 Token 信息仅在最终文本已提交后展示。

这避免“已完成”标签与未显示文本并存，也保证取消或失败不会抹掉已经从网络读取、但尚未提交到 React 状态的内容。

### 4. 首片段慢只展示真实请求状态

连接开始即创建助手占位消息并展示“正在连接模型”；收到首个 `delta` 后切换为“正在输出”。前端不伪造首片段，也不掩盖后端返回的超时或错误；错误消息继续使用现有显式重试入口。

该决定将“首片段慢”与“页面未流式渲染”区分开：前者是后端或 Provider 可观测问题，后者由本变更解决。

## Risks / Trade-offs

- [高频 `delta` 形成渲染积压] → 每个动画帧限制提交量并在流结束后继续排空；测试大批量事件，避免无限循环或消息顺序错误。
- [完成事件先于画面文本] → 将终止状态与元数据暂存，只有队列排空后才提交最终状态。
- [取消时遗失缓存片段] → 取消后停止网络读取，但先渲染本地已接收队列，再标记已取消。
- [迁移 HTTP 客户端引入回归] → 保持 Chat 事件类型、错误语义和 `AbortSignal` 行为不变，并以现有 SSE 解析测试作为迁移基线。

## Migration Plan

1. 新增 `services/http` 流式客户端并迁移现有 SSE 解析测试。
2. 调整 Chat 流式 API、Hook 与页面渲染队列，补充状态和视觉样式。
3. 运行前端单元测试、TypeScript 检查和生产构建；使用慢首片段与多 `delta` 流进行浏览器人工验收。
4. 若出现异常，移除渲染调度层可回退到现有直接追加方式；后端和 HTTP 契约无需回滚。
