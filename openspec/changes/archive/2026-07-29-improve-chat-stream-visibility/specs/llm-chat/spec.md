## MODIFIED Requirements

### Requirement: 前端展示单轮对话的完整请求生命周期

前端必须（MUST）通过业务请求层调用 LLM Chat API，并向用户展示单轮请求的连接中、输出中、成功、取消、失败和显式重试状态。普通 JSON 请求必须继续使用统一 Axios Client；带 POST JSON Body 的 SSE 流式请求必须通过 `services/http` 中的专用流式 HTTP 客户端读取，且不得由页面组件直接创建网络请求。

前端必须（MUST）按服务端接收顺序将每个有效 `delta` 追加到对应的助手消息。多个完整 SSE 帧即使在同一次底层读取中到达，也必须经过可观察的渲染调度，不得仅在流结束后显示最终拼接文本。前端不得伪造、重排或逐字拆分 Provider 返回的 `delta`。

#### Scenario: 用户发送有效消息并接收流式回答

- **WHEN** 用户输入非空消息并发起流式 Chat 请求
- **THEN** 页面立即展示用户消息和处于连接中的空助手消息
- **AND** 收到首个 `delta` 后将助手消息标记为正在输出
- **AND** 页面按接收顺序逐步追加每个已接收的 `delta`
- **AND** 输出中状态保持可见，直到流式回答终止

#### Scenario: 多个增量在同一读取批次到达

- **WHEN** 流式 HTTP 客户端在一次 `ReadableStream` 读取中解析出多个 `delta` 事件
- **THEN** 页面按事件顺序将这些增量加入渲染队列
- **AND** 渲染调度器在动画帧中提交增量，而不是以同一批 React 状态更新直接覆盖为最终文本
- **AND** 助手消息的最终文本与按顺序拼接所有 `delta` 的结果一致

#### Scenario: 流式回答正常完成

- **WHEN** 页面收到 `complete` 事件
- **THEN** 页面先提交所有已接收但尚未渲染的 `delta`
- **AND** 助手消息随后标记为已完成
- **AND** 页面展示模型标识、请求耗时和可用的 Token 信息

#### Scenario: 用户取消流式请求

- **WHEN** 用户在连接中或输出中取消流式请求
- **THEN** 页面停止读取新的流式内容
- **AND** 页面保留并渲染取消前已接收的助手文本
- **AND** 助手消息标记为已取消而不是普通服务错误
- **AND** 页面允许用户再次发送新请求

#### Scenario: 流式回答产生部分内容后失败

- **WHEN** 已接收至少一个 `delta` 后流式请求失败或收到 SSE `error` 事件
- **THEN** 页面保留并渲染失败前已接收的助手文本
- **AND** 助手消息标记为生成失败并显示可理解的错误信息
- **AND** 页面提供使用原始用户消息的显式重试入口
- **AND** 页面不自动重试

#### Scenario: 当前请求正在处理中

- **WHEN** LLM 请求处于连接中或输出中
- **THEN** 页面展示当前请求的准确状态
- **AND** 页面禁止重复发送同一时刻的请求
- **AND** 页面提供取消当前请求的操作

#### Scenario: 当前对话保持单轮能力边界

- **WHEN** 用户查看当前 Chat 页面
- **THEN** 页面明确当前为单轮模型调用验证
- **AND** 不宣称支持会话历史、上下文记忆、工具调用或 RAG 问答
