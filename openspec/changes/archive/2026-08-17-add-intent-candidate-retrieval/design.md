## Context

能力目录给出了受控能力集合，但不应把全部条目连同用户输入直接交给 LLM。候选召回需要在目录内选出少量语义相关条目，同时与政策知识检索完全隔离。

## Goals / Non-Goals

**Goals:**

- 基于通用 Embedding 和能力目录召回有限候选。
- 建立只服务能力理解的独立内存索引模型。
- 返回能力代码、相似度和可解释元数据，供后续识别使用。

**Non-Goals:**

- 不引入 pgvector、政策文档、引用证据、RAG rerank 或数据库表。
- 不自行识别最终意图，不执行任何能力。

## Decisions

### 1. 索引对象只来自能力目录

每个索引记录由能力描述、同义表达、正反例和检索元数据构成，关联稳定能力代码。不得写入政策文档切块，也不得调用知识库 Repository。

### 2. 首版使用内存索引和可配置的候选上限

目录初始化后生成向量并保存在进程内；查询使用余弦相似度返回不超过配置上限的候选，默认上限为 5。先验证能力语料与阈值，再决定是否持久化。

### 3. 召回失败返回显式不可用结果

Embedding 或索引构建失败时，服务返回可识别的失败，不以全量目录或任意默认能力替代。后续网关将该结果转换为澄清或稍后重试提示。

## Risks / Trade-offs

- [小型目录使用向量的收益有限] → 保持实现轻量，并用规则和可配置阈值补充。
- [相似文本误召回] → 召回只产生候选，最终仍由结构化 LLM、代码校验和用户确认决定。
- [进程重启造成索引重建延迟] → 首版只在启动或目录更新时构建；规模增长后另行评估持久化。

## Migration Plan

在目录和 Embedding Port 可用后接入内存索引。无数据迁移；异常时关闭统一入口候选召回，不影响既有政策 RAG 或 Agent 路径。
