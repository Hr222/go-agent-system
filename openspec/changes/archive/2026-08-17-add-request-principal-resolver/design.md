## Context

平台能力目录可以声明某项能力需要的权限，但当前项目尚未有用户、登录或认证模块。统一交互入口若读取请求体、查询参数、HTTP Header 或 LLM 输出中自报的角色和权限，就会让调用方伪造权限并绕过受保护能力。

本变更只建立认证授权的边界：HTTP 适配层把请求中可供认证适配器检查的上下文交给主体解析器；应用层和交互流程只消费解析后的请求主体。首版没有可信认证凭据，因此所有请求都被视为匿名主体和空权限集合。

## Goals / Non-Goals

**Goals:**

- 提供稳定的 `RequestPrincipal`，承载服务端确认的主体标识、认证状态和权限集合。
- 提供协议无关的 `PrincipalResolverPort`，使 JWT、Session、SSO 或内部权限服务能够在未来替换 HTTP 适配器实现。
- 在 HTTP 层提供依赖注入入口；首版匿名解析器忽略客户端自报权限并返回零权限主体。
- 让能力目录声明的权限能够由未来统一入口安全消费，而不把认证逻辑混入 LLM、Agent 或能力目录。

**Non-Goals:**

- 不实现用户表、登录、注册、JWT、Session、SSO、角色管理或权限数据库。
- 不增加认证 HTTP 接口、前端账号页面、数据库迁移或持久化主体状态。
- 不在本变更中实现 Interaction Gateway、能力授权决策、意图识别或 Agent 分发。

## Decisions

### 使用请求主体值对象作为唯一应用层授权输入

`RequestPrincipal` 包含 `subject`、不可变权限集合和 `authenticated` 标记。业务流程只接收该值对象，不读取原始请求 Header 或客户端提交的权限字段。

这样把“已验证的身份事实”和“不可信的请求输入”隔离开来，后续替换认证实现时不会改变目录、意图识别或分发器的契约。权限以集合存储；对外提供稳定排序后的元组，避免测试、日志和下游应用输入因集合顺序而不确定。

备选方案是在每个业务接口中直接解析 `Authorization` Header。该方案会把具体认证协议散布到多个接口，也难以替换，因此不采用。

### 以 Port 隔离认证协议，并在 HTTP 层组装

`PrincipalResolverPort` 接收协议中立的 `PrincipalResolutionContext` 并返回 `RequestPrincipal`。HTTP 依赖负责提取请求上下文和获得解析器，业务层不依赖 FastAPI `Request` 或认证协议。

首版 `AnonymousPrincipalResolver` 是唯一组装实现，并明确丢弃请求上下文。未来认证模块可在 Composition Root 或 HTTP 依赖中换成 JWT、Session、SSO 或内部身份服务适配器，无需修改能力目录或交互应用层。

备选方案是预先引入 JWT 中间件、用户数据库和角色系统。当前尚无用户产品需求和可信身份来源，提前实现会虚构领域模型并扩大本周范围，因此不采用。

### 默认拒绝而不是默认放行

匿名主体的 `subject` 为空、`authenticated` 为 `False`、权限集合为空。任何需要目录权限的能力在后续网关接入该主体前都必须判定为不可调用；客户端 Header、请求体、查询参数和模型输出中的权限、角色、能力代码或分发键均不能改变该结论。

这使未完成用户模块时的默认行为是可预测且安全的。公开能力可通过目录将权限要求留空，而不是让匿名解析器伪造权限。

## Risks / Trade-offs

- [当前所有受保护能力不可用] → 首版只允许目录中无权限要求的能力；集成测试通过注入可信静态解析器覆盖受保护能力的完整链路。
- [Port 被误用为认证实现] → 文档和规格明确该 Port 只消费可信认证结果，不能把客户端自报字段直接转成权限。
- [未来适配器来源不一致] → 后续 JWT、Session、SSO 适配器必须先验证凭据，再构造 `RequestPrincipal`；业务层不接受绕过 Port 的权限输入。

## Migration Plan

本变更没有数据迁移，也不改变现有业务 HTTP 接口。部署后，新增的 HTTP 依赖可被统一交互入口消费；在用户认证模块完成前维持匿名零权限实现。

后续接入认证时，新增并组装一个 `PrincipalResolverPort` 适配器，使用经验证的服务端身份结果构造主体。若新适配器出现故障，应拒绝受保护能力调用或回退为匿名主体，不得回退为客户端自报权限。

## Open Questions

- 未来用户模块采用 JWT、服务端 Session、企业 SSO 还是内部身份服务，由产品的部署和租户模型确定；这不影响本变更定义的 Port 契约。
- 公开能力是否需要单独的访问速率限制，留待统一交互入口与网关限流设计确定。
