## ADDED Requirements

### Requirement: 确认提议不具备执行权
系统 MUST 将有效识别结果转换为待确认提议；提议只包含受控能力代码、标准化输入、确认信息和固定分发键，不得包含可执行 URL、工具名称、类名或执行器引用。

#### Scenario: 用户尚未确认
- **WHEN** 系统已生成待确认提议但未收到明确确认
- **THEN** 系统返回待确认状态
- **AND** 系统不启动 Agent、RAG、政策判断或其他业务能力

### Requirement: 取消会终止当前确认提议
系统 MUST 在收到取消时将当前确认提议标记为不可分发，并返回取消结果。

#### Scenario: 用户取消提议
- **WHEN** 用户对待确认提议发出取消
- **THEN** 系统返回已取消状态
- **AND** 该提议不能再被批准或分发

### Requirement: 确认状态不成为长期工作流
系统 MUST 将首版确认限制在当前请求生命周期，不得因此创建 Conversation 持久化记录、Task 状态或后台执行。

#### Scenario: 确认请求结束
- **WHEN** 用户取消或确认流程结束
- **THEN** 系统不保留跨会话的待执行动作
- **AND** 系统不创建任务恢复记录
