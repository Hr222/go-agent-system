## Context

Conversation 已有主体范围的话题概括更新能力，并在服务端完成输入校验、所有权校验和持久化。当前 Chat 侧栏缺少就近的重命名操作入口。本子 change 只接入前端交互，不改变 `Conversation` 的领域模型、端口、HTTP 路由或数据库结构。

## Goals / Non-Goals

**Goals:**

- 从会话项更多菜单打开重命名编辑器。
- 通过既有 `useUpdateConversationTopicSummary` 调用主体范围接口保存名称或清除名称。
- 在保存期间禁用编辑操作；成功后关闭编辑器并使会话列表缓存失效；失败时保留草稿并显示错误。
- 保证菜单按钮及编辑操作不会触发会话切换。

**Non-Goals:**

- 不实现删除、置顶、分享、多选或批量操作。
- 不新增 HTTP 接口、数据库迁移或新的领域服务。
- 不修改首轮话题概括生成规则。

## Decisions

### 1. 重命名复用话题概括，而不新增名称字段

会话标题的持久化语义已经由 `topic_summary` 承担。前端将去除首尾空白后的非空文本提交为 `topic_summary`；空白输入提交 `null`，由现有接口清除概括并回退至日期标题。这样保持单一事实来源，也沿用既有主体隔离。

### 2. 编辑状态局限于 Chat 页面

Chat 页面维护正在编辑的会话标识、草稿和错误状态。菜单开启重命名时初始化草稿，保存成功后关闭编辑器；失败不关闭，避免用户重新输入。React Query mutation 成功时使列表缓存失效，服务端摘要是列表最终顺序和标题的来源。

### 3. 无新增后端组装或迁移

既有 HTTP 路由经 Conversation 应用层完成访问校验和更新，前端仅调用 API 封装。因此不增加 composition root、端口适配器或数据库迁移。

## Risks / Trade-offs

- [用户误清除名称] → 空白提交明确映射为既有的清除语义，列表以日期标题回退。
- [保存失败丢失输入] → 失败时保留草稿和编辑器，并显示可读错误。
- [菜单点击切换会话] → 更多按钮阻止事件冒泡，测试覆盖菜单打开和保存路径。
- [并发更新导致过时标题] → 成功后依赖失效并重新读取服务端摘要，不在前端固化乐观标题。
