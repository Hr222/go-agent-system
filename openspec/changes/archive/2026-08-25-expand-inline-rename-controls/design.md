## Context

普通会话项为右侧“…”菜单预留 `34px` 内边距。编辑状态已经不渲染菜单，但仍复用了该内边距；输入框还以 `width: 100%` 参与 flex 布局，无法清晰表达“填满剩余空间”的意图。

## Goals / Non-Goals

**Goals:**

- 让编辑项回收已隐藏菜单的右侧空间。
- 让输入框填满除会话图标、置顶标识（如有）、确认和取消按钮外的可用宽度。
- 保持确认、取消按钮尺寸稳定且不会被输入内容挤压。

**Non-Goals:**

- 不改变正常会话项的菜单空间、标题截断或交互。
- 不调整 API、持久化、输入长度和保存流程。

## Decisions

### 只为编辑项覆盖右侧内边距

为 `conversationItemEditing` 覆盖普通项为菜单预留的右侧内边距，而不修改基础会话项样式。普通状态继续给“…”保留空间；编辑状态因不渲染菜单而获得该空间。

### 用 flex 明确输入与操作按钮的分工

输入框使用 `flex: 1 1 auto` 和 `width: auto`，在可用空间内伸缩；确认、取消按钮维持固定 flex 基准。这样即使会话已置顶，也由输入框先收缩，按钮不会错位或改变尺寸。

## Risks / Trade-offs

- [窄侧栏或置顶图标减少输入空间] → 输入框最小宽度为零并允许收缩，固定图标按钮保留可点击尺寸。
- [普通项受到布局回归影响] → 覆盖仅绑定编辑状态类，正常项的内边距保持不变。

## Migration Plan

纯 CSS 布局调整，无数据迁移；回滚可删除编辑状态的内边距和输入 flex 覆盖。
