## Context

Chat 会话项通过 `renameConversationId` 区分普通展示和内联编辑。当前编辑分支已经把标题替换为输入、确认和取消控件，但菜单容器仍在同一会话项右侧渲染。

## Goals / Non-Goals

**Goals:**

- 编辑当前会话名称时移除该项的“…”操作入口，减少竞争操作和横向拥挤。
- 在保存成功或取消编辑后恢复菜单。
- 保持其他会话项的菜单和当前的失败重试行为不变。

**Non-Goals:**

- 不修改会话名称 API、输入校验、列表排序或置顶行为。
- 不增加新的持久化或独立 UI 状态。

## Decisions

### 由编辑会话 ID 决定菜单渲染

仅当 `renameConversationId` 不等于当前列表项 ID 时渲染菜单容器。保存成功和取消均会清空该 ID，因此无需额外的“菜单已隐藏”状态，也不会引入状态复位顺序问题。

失败时编辑状态和草稿保持不变，菜单也持续隐藏，使用户只能修正草稿、再次保存或取消；这与现有失败留在目标项内的交互一致。

备选方案是使用 CSS 隐藏菜单。条件渲染不会保留不可操作的焦点目标或可能打开的菜单内容，语义更准确，因此采用。

## Risks / Trade-offs

- [保存失败后用户需要其他操作] → 用户可以取消编辑，菜单立即恢复；不会丢失已保存的服务端数据。
- [条件切换遗留打开菜单状态] → 发起重命名时既有逻辑已关闭菜单，渲染条件作为第二层保证。

## Migration Plan

纯前端展示调整，无数据迁移；回滚时恢复菜单容器的无条件渲染即可。
