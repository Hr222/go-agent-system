## Context

Chat 侧栏的会话菜单已经可以发起重命名，并使用 `renameConversationId`、`renameDraft` 和既有话题概括更新 mutation 管理编辑状态。当前编辑器脱离会话列表，固定出现在侧栏底部，造成目标不明确和列表空间被压缩的问题。

## Goals / Non-Goals

**Goals:**

- 让编辑状态与用户在菜单中选择的会话项保持同位。
- 保留既有保存、取消、输入长度限制、请求中禁用和失败重试语义。
- 使编辑中的会话仍可识别日期、置顶状态与更多操作入口。

**Non-Goals:**

- 不修改话题概括 API、数据库、服务端校验或会话排序。
- 不支持同时编辑多个会话，也不增加批量重命名。
- 不改变重命名成功后的列表缓存刷新和消息历史行为。

## Decisions

### 在目标会话标题位置渲染编辑器

当 `renameConversationId` 等于列表项 ID 时，用受控输入框替换该项的普通标题，并在同一行提供确认和取消图标按钮。日期副标题、置顶图标和菜单区域维持在原项中，避免用户失去会话上下文。

备选方案是在侧栏顶部或底部保留共享编辑器。该方案不能表达编辑目标，且会改变列表可见区域，因此不采用。

### 保持单一编辑状态和既有保存流程

继续使用现有的单一会话 ID 与草稿状态。点击菜单中的重命名会关闭菜单并替换该项标题；确认沿用更新 mutation，取消清除编辑状态。请求失败只显示目标项内的错误并保留草稿；请求进行时禁用该项的确认、取消与输入，避免重复提交或丢失结果。

备选方案是为每个列表项维护独立草稿。列表只允许单项重命名，独立状态会增加无用复杂度和状态清理风险，因此不采用。

### 不将编辑框嵌入会话选择按钮

会话项外层继续负责选择会话，编辑控件在该按钮之外的同一行容器中渲染。这样输入、确认和取消不会触发会话切换，也不会形成嵌套交互元素。

## Risks / Trade-offs

- [窄侧栏内标题、输入和图标空间不足] → 输入使用弹性宽度、固定尺寸图标按钮，并在窄视图中保持可点击区域。
- [编辑时用户误触会话选择] → 编辑控件位于选择按钮之外，编辑状态下点击编辑区域不会冒泡到会话选择逻辑。
- [保存失败后用户无法辨识失败对象] → 错误反馈仅在目标会话项内显示，并保留草稿和输入焦点。

## Migration Plan

纯前端呈现调整，无数据迁移。部署后新页面直接使用内联编辑；回滚只需恢复旧的侧栏底部编辑器实现。
