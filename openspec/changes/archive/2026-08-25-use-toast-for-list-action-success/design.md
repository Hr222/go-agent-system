## Context

会话列表页面已经通过 Ant Design `message` 展示置顶和删除失败反馈，重命名成功也已使用全局成功浮层。但置顶、取消置顶和删除成功仍写入 `listActionNotice`，在侧栏顶部渲染一条可关闭的共享状态条。该状态只承载一次性操作结果，且会占用会话列表空间。

## Goals / Non-Goals

**Goals:**

- 置顶、取消置顶和删除成功均调用 Ant Design `message.success`。
- 移除 `listActionNotice` 状态、侧栏成功提示渲染和关闭按钮。
- 保持操作请求、列表刷新、删除确认、当前会话清理和失败反馈不变。
- 用组件测试验证成功消息内容以及侧栏不再出现成功状态。

**Non-Goals:**

- 不改变置顶上限、排序、删除级联或任何 HTTP/数据库契约。
- 不改变加载状态、列表错误、重命名错误和置顶/删除失败提示。
- 不引入新的通知组件或第三方依赖。

## Decisions

### 复用现有 Ant Design 消息 API

页面已经导入 `message` 并使用 `message.error`。成功分支直接调用 `message.success`，分别传入“已置顶会话”“已取消置顶”和“会话已删除”，避免额外状态管理和重复通知组件。

### 删除共享成功状态而非保留空壳

`listActionNotice` 只服务于这三类成功操作，重命名已不再使用它。移除状态和 JSX 后，侧栏不再为一次性反馈预留空间；加载中的 `role="status"` 和失败的 `role="alert"` 保持独立。

### 以组件测试锁定反馈通道

在现有 Ant Design mock 中增加并复用 `messageSuccess`，为置顶、取消置顶和删除成功增加断言，同时确认侧栏没有共享成功状态。失败测试继续断言 `message.error`，防止成功反馈迁移时误伤错误反馈。

## Risks / Trade-offs

- [用户错过短暂浮层] → 浮层只确认已完成的操作；列表顺序、目标会话移除或置顶图标仍提供持久结果。
- [成功消息文案与既有界面不一致] → 沿用当前侧栏显示的三条中文文案，变更只调整展示载体。

## Migration Plan

仅发布前端静态资源，无数据库迁移、接口变更或发布顺序要求。回滚时恢复原成功分支和共享提示节点即可。
