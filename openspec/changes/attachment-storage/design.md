## Context

现有上传实现已经验证了临时目录、随机 ID、扩展名白名单、大小上限、原子改名和过期清理。该 Change 以其安全策略为基础，通过通用 Adapter 接入附件契约。

## Goals / Non-Goals

**Goals:**

- 使用真实临时文件系统验证动态附件生命周期。
- 保证路径隔离、部分文件清理和 TTL 清理。

**Non-Goals:**

- 不提供 HTTP 路由或主体绑定。
- 不改变政策专用配置和接口。

## Decisions

- 保留现有安全文件写入策略，抽取可配置的大小、保留期和媒体类型策略。
- 通过 Adapter 复用旧实现，避免一次性重命名造成政策回归。
- 测试使用 `tmp_path` 和可注入时钟，不使用静态路径或固定附件 ID。

## Risks / Trade-offs

- [通用配置与政策配置混淆] -> 明确分离附件命名空间和默认值，旧配置继续有效。
- [文件残留] -> 上传失败、过期、显式丢弃均验证目录为空。

## Migration Plan

先新增通用实现并保留旧实现；确认回归通过后再由上传 HTTP Change 选择新实现。

## Open Questions

持久化附件是否需要对象存储由后续部署需求决定。
