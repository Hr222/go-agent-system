## MODIFIED Requirements

### Requirement: 系统从能力目录召回有限意图候选
系统 MUST 根据用户文本、能力目录的检索元数据和当前主体的权限范围，返回不超过配置上限的相关候选；每个候选 MUST 包含稳定能力代码和可解释的相关性信息。候选索引的构建、就绪检查和查询 MUST 使用同一个规范化权限范围，且不得将一个权限范围的索引或候选复用于另一个范围。成功构建的权限范围索引 MUST 在同一后端进程的后续请求中复用；普通查询或已经就绪的范围 MUST NOT 重复读取完整目录并重新生成全量索引 Embedding。

#### Scenario: 用户请求匹配多个能力
- **WHEN** 用户文本与当前主体可访问的多个已启用能力相关
- **THEN** 系统按相关性返回有限候选集合
- **AND** 候选数量不超过配置上限

#### Scenario: 没有足够相关候选
- **WHEN** 当前权限范围内所有目录条目均未达到召回条件
- **THEN** 系统返回空候选结果
- **AND** 系统不替换为任意默认能力

#### Scenario: 不同权限范围使用独立候选索引
- **WHEN** 一个具有受限能力权限的主体已经成功构建候选索引，另一个不具有该权限的主体发起查询
- **THEN** 系统只使用后一个主体权限范围的索引和目录条目
- **AND** 查询结果不得包含仅对前一个主体可见的能力代码

#### Scenario: 当前权限范围尚未成功构建索引
- **WHEN** 调用方以某个权限范围查询，但该范围没有成功构建索引
- **THEN** 系统返回候选召回不可用结果
- **AND** 系统不得复用其他权限范围的索引或返回全量目录

#### Scenario: 已就绪权限范围的索引跨请求复用
- **WHEN** 同一后端进程中两个请求使用相同的规范化权限范围进行候选查询
- **THEN** 第一个请求成功构建的索引可供第二个请求复用
- **AND** 第二个请求不得再次读取完整能力目录或生成全量索引 Embedding

### Requirement: 能力候选索引与政策知识索引隔离
系统 MUST 使用独立的能力候选索引，并禁止向 `kb_policy_chunk`、政策 Repository 或 RAG 检索管线写入或读取能力描述。

#### Scenario: 构建能力候选索引
- **WHEN** 目录条目需要生成检索向量
- **THEN** 系统只使用能力描述、示例和检索元数据构建候选索引
- **AND** 系统不读取政策文档切块

### Requirement: 召回故障不会放宽执行边界
系统 MUST 将 Embedding、候选索引或当前权限范围的索引故障作为可识别失败返回，且不得返回全量目录或其他权限范围的候选集来替代候选集。某一权限范围重建失败时，系统 MAY 保留该范围此前成功的索引，但不得影响其他范围。

#### Scenario: Embedding Provider 不可用
- **WHEN** 候选召回期间无法生成查询向量
- **THEN** 系统返回候选召回不可用结果
- **AND** 系统不产生可执行能力或分发请求

#### Scenario: 某一权限范围重建失败
- **WHEN** 某个权限范围的目录索引重建失败且该范围此前已有成功索引
- **THEN** 系统保留该范围此前成功的索引
- **AND** 系统不得以其他权限范围的索引作为回退
