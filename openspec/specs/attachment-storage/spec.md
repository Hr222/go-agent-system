# attachment-storage Specification

## Purpose
定义服务端隔离的动态附件暂存、完整写入校验和过期清理能力，确保附件引用不暴露物理路径且失败写入不会留下可读取的残留文件。
## Requirements
### Requirement: 安全暂存动态附件

系统 MUST 将上传内容写入服务端隔离的临时目录，使用随机附件 ID，并在完整写入和校验后才使文件可读取。

#### Scenario: 成功暂存
- **WHEN** 使用真实临时文件流提交合法文件
- **THEN** 系统返回动态附件引用和正确大小
- **AND** 读取内容与提交内容一致

#### Scenario: 超过大小限制
- **WHEN** 文件流超过配置的大小上限
- **THEN** 暂存失败
- **AND** 不留下可读取的部分文件

#### Scenario: 路径越界输入
- **WHEN** 使用非服务端生成的附件 ID 读取文件
- **THEN** 系统拒绝请求
- **AND** 不访问附件根目录之外的路径

### Requirement: 附件过期清理

系统 MUST 清理超过保留期的暂存附件，并使其引用不可继续读取。

#### Scenario: TTL 到期
- **WHEN** 暂存目录的时间超过保留期并执行清理
- **THEN** 目录被删除
- **AND** 后续读取返回附件不可用
