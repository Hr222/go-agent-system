## Purpose

在 HTTP 边界将可信认证结果转换为统一、可替换的请求主体，使能力授权只消费服务端确认的身份与权限，不依赖客户端、LLM 或调用参数自报的授权信息。

## Requirements

### Requirement: 请求主体解析边界
系统 MUST 在 HTTP 适配层将可信认证结果解析为请求主体，供后续统一交互入口和能力授权使用。请求主体 MUST 包含主体标识、认证状态和权限集合；业务层 MUST 消费该主体，而不是自行读取原始 HTTP 请求。

#### Scenario: 认证适配器提供可信主体
- **WHEN** 已接入的认证适配器验证请求凭据并解析出主体与权限
- **THEN** 系统向后续业务流程提供该主体和权限集合
- **AND** 后续业务流程无需了解所使用的认证协议

### Requirement: 匿名请求默认零权限
在未接入认证模块时，系统 MUST 使用匿名主体解析器。匿名主体 MUST 未认证、没有主体标识且权限集合为空。

#### Scenario: 未认证请求访问统一入口
- **WHEN** 请求没有通过已配置的认证适配器获得可信身份
- **THEN** 系统将该请求解析为匿名零权限主体
- **AND** 后续需要目录权限的能力授权结果为拒绝

### Requirement: 不信任客户端自报授权信息
主体解析器 MUST 不将客户端请求体、查询参数、HTTP Header 或模型输出中自报的权限、角色、能力代码或分发键视为授权依据。只有经过认证适配器验证的服务端身份结果可以构造非空权限集合。

#### Scenario: 客户端伪造权限 Header
- **WHEN** 未认证请求在 Header 中提交受保护能力所需的权限或角色
- **THEN** 匿名主体解析器仍返回空权限集合
- **AND** 该请求不能因该 Header 获得受保护能力的调用资格

### Requirement: 可替换的认证实现
系统 MUST 通过稳定的请求主体解析契约支持替换认证实现。替换为 JWT、Session、SSO 或内部身份服务后，能力目录和业务流程的请求主体消费契约 MUST 保持不变。

#### Scenario: 接入新的认证适配器
- **WHEN** 系统配置新的已验证身份解析器
- **THEN** HTTP 适配层使用该解析器构造请求主体
- **AND** 业务流程继续以相同的请求主体字段读取权限
